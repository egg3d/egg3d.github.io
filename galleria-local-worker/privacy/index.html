Privacy Policy

How GALLERIA Local Worker handles Google user data

Effective date: August 28, 2026

This policy applies only to GALLERIA Local Worker, its Gmail Secondary Queue integration, and its Google Drive Temporary Artifact Transport integration.

1. Application and operator

GALLERIA Local Worker is a private desktop automation tool operated by the owner of the authorized Google account. It runs locally on the operator's Windows PC and is not offered as a public email service.

2. Google data accessed

The Gmail integration requests the Gmail read-only OAuth scope. It may read Gmail message metadata and content required to find and validate self-sent queue messages that use the fixed subject prefix [GALLERIA-V2-JOB] and the expected JSON envelope.

The Gmail integration does not request permission to send, modify, label, or delete messages. A separate Drive integration requests only https://www.googleapis.com/auth/drive.file. It may create a temporary artifact file through the operator-only bounded uploader, or read one exact artifact file explicitly granted to this OAuth app. It does not request access to the user's whole Drive, Calendar, Contacts, or other Google services.

3. How Google data is used

Gmail data is used only to discover eligible secondary-queue jobs, validate the expected sender, recipient, queue, target machine, protocol, session, payload hash, and replay status, and record the minimal local audit state needed to prevent duplicate processing.

Drive data is used only to obtain metadata and package bytes for one descriptor-supplied file ID, validate its expected size and SHA-256, and create immutable local staging. Drive is not used as a queue and is not polled, listed, searched, or traversed. Drive filenames and folders are not authority.

Google user data is not used for advertising, profiling, marketing, or training AI models.

4. Local storage and security

Gmail and Drive OAuth credentials are stored separately on the operator's Windows PC and encrypted for the current Windows user with Windows Data Protection API (DPAPI). Plaintext OAuth tokens are not stored in source control, GitHub Pages, Gmail messages, job payloads, or application logs.

The app may retain local replay-ledger entries and audit metadata such as message identifiers, validation outcomes, and processing timestamps. These records are kept locally for operational integrity and troubleshooting.

Downloaded artifact bytes are streamed into a bounded local staging area, verified against an expected size and SHA-256, atomically finalized read-only, and then processed locally. Tokens and client secrets are never written to Notion, Gmail, jobs, logs, evidence, configuration, or manifests.

5. Sharing, transfer, and sale

Google user data is not sold, rented, shared with advertisers, or transferred to third parties. Data is processed locally by the operator's worker except where transmission to Google is required to use the Gmail and Drive APIs. The Drive integration does not create public or anyone-with-link permissions. Disclosure may occur only if required by applicable law.

6. Retention and deletion

Protected OAuth credentials and local audit records are retained on the operator's PC until they are manually removed or are no longer needed. Temporary Drive artifacts are not deleted automatically. A test artifact may be removed only by its exact file ID after verification evidence is finalized; production retention and cleanup require a separate policy and approval. The operator can delete the protected local credentials and related local records at any time.

7. Revoking access

Access can be revoked from the Google Account's third-party connections page. The operator can also stop the local worker and remove the relevant encrypted credential. Gmail and Drive grants are separate. After revocation, the affected integration can no longer access Google data unless authorization is granted again.

GALLERIA Local Worker's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

9. Changes to this policy

This policy may be updated when the app's operation or legal requirements change. The effective date above will be revised when a material update is published.
