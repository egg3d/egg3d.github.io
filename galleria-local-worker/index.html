Private desktop automation

Local-first queue processing and bounded artifact transport for one trusted operator.

GALLERIA Local Worker runs on the owner's Windows PC. Its Gmail Secondary Queue integration uses read-only access to discover and validate narrowly defined job messages sent by the same operator. A separate Google Drive integration can transfer one explicitly identified update artifact at a time.

Purpose

A bounded secondary queue

What it reads

The app searches the authorized Gmail account for self-sent messages with a fixed subject prefix and a fixed JSON job envelope. It reads only the message data needed to validate and process those queue entries.

How it protects the queue

Messages must pass checks for the expected sender, recipient, queue, target machine, protocol, session, payload hash, and replay status before they can be accepted.

What it cannot do

The Gmail integration cannot send, modify, label, or delete email. The separate Drive artifact integration cannot list, search, traverse folders, share, or read unrelated files. It uses only per-file drive.file access for explicitly created or granted artifacts.

Security

Credentials stay protected on the local PC

OAuth credentials are encrypted for the current Windows user with Windows Data Protection API (DPAPI). Plaintext access and refresh tokens are not stored in source control, GitHub Pages, Gmail messages, job payloads, or application logs.

Gmail and Drive use separate OAuth clients, scopes, encrypted credential files, and runtime roles. Google Drive is temporary package-byte transport, not a queue. Notion and Gmail remain the control plane.

This tool is operated privately and is not offered as a public email service. For full details about data access, use, retention, and revocation, see the GALLERIA Local Worker Privacy Policy.
